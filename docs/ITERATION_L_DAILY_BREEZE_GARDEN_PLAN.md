## 1. 当前问题

当前局内已经具备落叶层、普通三连邻域清扫和四连方向清风，但实际棋盘仍是固定 `7 x 7` 满格、垂直下落和随机铺花。关卡差异主要来自收集数字、花色和少量落叶坐标，因此玩家知道规则后，后续多数操作仍是寻找现成三连。

问题不是关卡数量不足，而是每局缺少三个体验阶段：

1. 开局看见结构后形成路线判断。
2. 中局为了一个明确空间目标主动制造四连。
3. 达成后出现可记忆的连续感官反馈，而不是只增加计数。

## 1.1 迭代目标

完成晨露连锁的可玩规则切片，再以确定性、可复盘的每日布局验证同一套交换操作能否产生明显不同的路线判断与连锁高潮。试玩数据只保存在本地 JSONL，不联网、不上传个人信息，也不接入排行或分享。

## 2. 外部玩法取舍

### 可借鉴

- `羊了个羊` 的规则保持稳定，但遮挡拓扑和每日同题让玩家先观察结构，再反复验证路线；每日同题也形成可讨论对象。
- `Royal Match` 通过障碍与位置关系改变决策，例如相邻消除、多层处理、按颜色处理、下落收集和每步移动的传送带，而不是只提高目标数字。
- `Candy Crush Saga` 用主题事件改变局内物件和阶段目标，但基础匹配动作保持稳定。
- `Block Blast` 仍使用简单放置规则，以固定棋盘和不同挑战目标提供短局体验。

### 明确不复制

- 不改成槽位式三张消除，避免失去当前交换三消基础并与同类高度重叠。
- 不采用 `羊了个羊` 约千分级通关率的挫败模型；本项目目标仍是低压力但需要思考。
- 不一次加入炸弹、彩球、传送门、变向重力、倒计时和技能卡。
- 不以大量新障碍作为内容产能主轴，避免变成传统三消障碍清单。

## 3. 产品裁决

选择“每日风庭”，而不是继续线性堆关。

一句话规则：

> 每天进入同一座落叶花庭，通过三连引风、四连定向，把藏在落叶中的晨露花苞依次吹开，形成一次可规划的连锁绽放。

基础交换方式不变，新增决策来自布局：

- 普通三连仍清扫匹配位置及相邻落叶，提供稳定进度。
- 四连仍形成整行或整列清风，是主动规划的大范围手段。
- 晨露花苞位于落叶层下；对应落叶被扫开时，花苞绽放并清扫十字邻域。
- 花苞清扫命中另一枚花苞时继续连锁，形成局内高潮。
- 每日指定一个推荐风向；同方向四连会让花苞十字多延伸一格，但不作为唯一通关条件。

### 3.1 目标映射与可评估口径

| 产品目标 | 可见机制 | 用户感知 | 可评估口径 |
|----------|----------|----------|------------|
| 每局先观察再行动 | 落叶拓扑、可见花苞和推荐风向 | 能说出先要清扫或连接的区域 | 无讲解试玩中至少 `4/5` 说明花苞连锁规则 |
| 中局主动制造机会 | 方向四连与相邻花苞路线 | 会为了路线而非随机消除制造四连 | 至少 `3/5` 主动完成一次推荐方向四连 |
| 形成一次记忆点 | 晨露十字扩散、递进音效和连锁文案 | 连锁因果清楚且不刺眼 | 至少 `4/5` 认为反馈清楚舒服，最大连锁与重试率可从本地事件汇总 |

## 4. 每日变化来源

首版只使用可控组合，不做完全随机内容：

| 变化维度 | 首版范围 | 玩家感知 |
|----------|----------|----------|
| 落叶拓扑 | 环形、双岛、斜径 3 个母版 | 开局关注区域不同 |
| 变换方式 | 原型、水平镜像、垂直镜像、180 度旋转 | 同一母版产生不同路线 |
| 花苞位置 | 每个母版 2-4 个合法节点 | 连锁顺序不同 |
| 推荐风向 | 横向或纵向 | 四连规划方向不同 |
| 初始棋盘 | 日期种子确定 | 同一天重试可复盘，不靠反复刷开局 |

日期标识采用版本化种子，例如 `daily_v1_20260821`。模板、变换和初始棋盘都由该种子决定，离线环境也可复现。后续修改生成规则时提升版本号，不改变历史挑战定义。

## 5. 感官反馈目标

晨露连锁必须同时提供因果和节奏：

1. 命中前：花苞在落叶下轻微呼吸发光，提示潜在路线，不完全隐藏信息。
2. 命中时：落叶先掀开，再出现花苞绽放，避免动画因果错位。
3. 连锁中：清风沿格子逐段传播；每一跳音高轻微上升，画面只做短促缩放，不使用强烈震屏。
4. 收束时：显示“晨露连锁 xN”和本次额外扫叶数，随后立即回到可操作状态。
5. 花园反馈：当天首次完成后，只点亮花园中的一处晨露景观，不再新增独立货币。

性能预算：单次连锁动画不超过 `1.2 秒`；低端设备粒子数量有上限；所有动画不改变逻辑结算结果。

## 6. 难度原则

难度来自路线选择，不来自信息欺骗或纯数值压缩：

- 玩家始终能看见花苞位置和推荐风向。
- 普通三连可以缓慢完成，四连和连锁用于节省步数。
- 每日挑战允许无限重试，不消耗生命或星光。
- 失败保留“今日最佳扫叶比例、最大连锁、最接近通关剩余步数”。
- 首版目标为 3 次尝试内通关率 `35%-65%`，不追求极低通过率。
- 若生成局面没有有效交换、目标不可达或必须依赖随机级联，则生成检查直接失败并回退到安全模板。

## 7. 产品入口

不新增首页第五个入口。复用“今日花礼”页面，将其升级为每日内容页：

- 上半区：`今日风庭`，展示布局缩略图、推荐风向、今日最佳和“开始挑战”。
- 下半区：保留现有每日任务和花礼领取。
- 首次通关后按钮变为“再试一次”，允许追求更少步数或更高连锁。
- 微信/抖音分享和地区排行不进入首版；先验证局面本身是否值得讨论。

## 8. 工程方案

### 8.1 数据结构

在现有关卡配置上增加可选字段：

```json
{
  "daily_challenge": {
    "challenge_id": "daily_v1_20260821",
    "layout_id": "double_island",
    "seed": 20260821,
    "preferred_direction": "horizontal"
  },
  "target": {
    "garden_layer": {
      "cells": [[1, 1], [1, 2]],
      "required": 2,
      "dew_buds": [[1, 2]]
    }
  }
}
```

`dew_buds` 只允许出现在 `cells` 中。标准化阶段删除越界、重复和不在落叶层中的节点。

### 8.2 模块边界

- 新增 `DailyChallengeService`：日期种子、模板选择、镜像旋转、配置校验、当日成绩。
- `Board`：保存花苞位置，清叶后解析花苞十字连锁，返回 `dew_bursts` 和新增清扫位置。
- `LevelSystem`：支持直接启动标准化配置，并统计最大花苞连锁。
- `SimpleGameController`：当前真实运行控制器，负责播放连锁反馈和记录事件；不在旧 `GameController` 重复实现。
- `BoardVisual`：花苞标记、传播路径和连锁结果动画。
- `DailyGiftUI`：展示今日配置和发起挑战，不承担规则计算。

当前运行时使用名为 `SimpleGameController` 的控制器，而仓库仍保留另一套 `GameController`。迭代 L 不允许双路实现新规则；后续单独完成命名和旧路径清理，避免玩法继续分叉。

### 8.3 确定性

- `Board` 不再对每日挑战使用全局 `randi()`，改用配置种子的局部 `RandomNumberGenerator`。
- 洗牌使用同一 RNG 的 Fisher-Yates，保证同日同版本初始棋盘一致。
- 自动化运行相同种子两次，网格、落叶、花苞和风向必须完全一致。

## 9. 分阶段目标

### L-1：晨露连锁规则切片

范围：

- 支持 `dew_buds` 配置和十字连锁。
- 先在 3 个测试布局中验证，不接每日入口和奖励。
- 完成逻辑、视觉、音效层级与试玩事件。

完成门槛：

- 单花苞、双花苞连锁、边界节点和重复命中均有自动化测试。
- 连锁只结算一次，不重复计数，不改变基础掉落顺序。
- 真实 `750 x 1334` 画面能在无说明时看出花苞位置和传播顺序。
- 5 次内部试玩中不存在结算错乱、动画期间可重复输入或胜负提前触发。

### L-2：每日风庭最小闭环

范围：

- 实现版本化日期种子、3 个母版和 4 种空间变换。
- 今日花礼页接入开始、结果和再次挑战。
- 保存当日最佳，不增加联网和排行榜。

完成门槛：

- 相同日期和版本在 100 次自动化生成中完全一致。
- 12 种模板组合均有有效移动，花苞合法，目标可完成。
- 日期切换后生成新挑战，旧成绩不污染新日期。
- 断网、改时区和旧存档不会导致崩溃；本地日期作弊首版只记录，不阻断。

### L-3：目标用户试玩

至少 5 名目标用户，无口头规则讲解，各体验 2 个不同日期样本。

通过门槛：

- 至少 `4/5` 能说出花苞被吹开后会继续清扫。
- 至少 `3/5` 会主动为推荐方向制造一次四连。
- 至少 `4/5` 认为两天的思考路线明显不同，而不是只换目标数字。
- 至少 `3/5` 主动重试失败局或通关后尝试优化一次。
- 3 次尝试内通关率位于 `35%-65%`。
- 至少 `4/5` 认为连锁反馈“清楚且舒服”，无人反馈刺眼、拖沓或结算错乱。

停止条件：任意两个理解指标低于门槛时，先调整花苞可视性、布局和反馈，不增加新机关；若两轮调整后仍未达到门槛，则终止每日模式扩展。

## 10. 试玩事件

新增本地事件：

- `daily_challenge_started`：挑战 ID、模板、变换、风向、尝试次数。
- `dew_bud_triggered`：位置、连锁序号、额外清扫数。
- `daily_challenge_settled`：胜负、剩余步数、最大连锁、扫叶比例。
- `daily_challenge_retried`：上局结果、上局最大连锁、重试间隔。

核心报告指标：首次理解代理、主动方向四连率、平均最大连锁、失败后重试率、三次内通关率和每日最佳提升率。

## 11. 本轮不做

- 不做不规则棋盘空洞、传送门或重力旋转；这些留到每日风庭本身通过试玩后评估。
- 不做广告换道具、生命限制或付费重试。
- 不做实时排行、好友墓碑、地区对抗或强分享任务。
- 不新增花园货币、技能树、卡牌和装备。
- 不将纯随机级联作为通关必要条件。

## 12. 完成定义

工程测试通过只代表规则可运行；只有 L-3 的理解、差异感、重试和舒适度门槛同时满足，才能继续增加新的每日布局或机关。产品目标不是让玩家重复通过更多关，而是每天用同一套简单操作完成一次不同、可复盘且有清风绽放记忆点的空间解题。
