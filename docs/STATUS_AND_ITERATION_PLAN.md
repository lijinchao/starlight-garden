## 1. 原始设计目标

根据 [GAME_DESIGN.md](./GAME_DESIGN.md)，项目的目标产品形态是：

- 面向 25-40 岁女性用户的治愈系休闲小游戏
- 以三消为主玩法，以花园成长为局外承接
- 核心循环为：`消除关卡 -> 获取奖励 -> 合成花朵 -> 装饰花园`
- 长线循环为：`收集花语 -> 解锁故事 -> 情感共鸣 -> 持续游玩`
- 产品表达强调“低压力、治愈感、失败不惩罚、碎片时间友好”

---

## 2. 当前版本的真实产品定位

当前仓库已经不是纯框架，而是一个可运行、可通关、带局外雏形的原型版本。

更准确的定位应为：

> “治愈题材三消原型 + 基础花园循环雏形”

它已经具备一条弱闭环：

`进入关卡 -> 三消过关 -> 获得花种 -> 花园种植 -> 成长收获星光 -> 星光用于失败续关 / 开局祝福 / 花园装饰`

但它还没有达到设计文档中“消除 + 合成 + 花园装饰 + 花语情感内容”的完整 MVP。

## 3. 当前已实现功能

### 3.1 已可游玩的功能

- 主菜单、开始游戏、进入花园、进入设置
- 7x7 棋盘三消基础规则
- 相邻交换、3 连消除、掉落补牌、连锁结算
- 基础收集型关卡目标
- 分数、步数、过关判定、失败判定
- 20 个关卡配置文件
- 通关后解锁下一关
- 通关后按关卡配置发放星光、花种和首通奖励
- 花园种植、成长计时、成熟收获
- 花园背包支持 3 级以内合成
- 收获后获得星光资源
- 失败后进入“休息时刻”，可消耗星光继续获得 5 步
- 开局前可消耗星光购买“星光祝福”获得额外 3 步
- 连续失败触发额外鼓励奖励（星光 + 花种）
- 通关、首通和失败结算发放花语碎片
- 花语碎片达到 5 个后解锁完整花语
- 主菜单可进入花语日记查看 6 种基础花进度与已解锁花语
- 主菜单可进入今日花礼查看每日任务
- 主菜单对花语日记和今日花礼做渐进解锁，降低早期局数心智负担
- 完成任意 1 局、收获花朵、获得花语碎片会推进每日任务
- 完成全部每日任务后可领取每日星光和花种奖励
- 花园中可用星光购买固定装饰
- 已购买装饰会提升花园氛围值并写入存档
- 胜利/失败弹窗使用首层结算摘要降噪，完整奖励数据仍保留
- 花园恢复阶段会在前三局逐段推进，并在菜单、花园和结算中可见
- 基础新手引导
- 基础设置页
- 本地存档
- 自动化测试覆盖结算、合成、经济与失败缓冲

### 3.2 已实现但仍属雏形的功能

- 关卡可配置可用元素类型和奖励掉落
- 失败弹窗、胜利弹窗、Toast 等反馈系统
- 音频管理、程序化素材生成、UI 主题工具
- 花园库存、槽位与合成数据结构
- 教程管理器与高亮引导流程

### 3.3 仅有数据或接口，尚未真正形成玩法的内容

- 特殊元素概率配置（炸弹、彩虹花）
- 双倍奖励广告入口（当前不在胜利弹窗暴露）
- 大型花园装饰系统（自由摆放、主题皮肤、长期图鉴）
- 治愈日记 / 剧情系统
- 成就、活动
- 微信生态、分享、好友、排行榜

## 4. 设计目标与当前实现差距

### 4.1 核心循环差距

设计目标：

`消除 -> 奖励 -> 合成 -> 装饰 -> 反哺下一局`

当前实际：

`消除 -> 配置化奖励 -> 种植/合成 -> 收获星光 -> 续关/开局祝福/花园装饰`

差距在于：

- 已补上“合成”这一步，但仍是最小版
- 已补上固定装饰购买与氛围值，但还没有自由摆放和主题装扮
- 星光已具备两种局内用途，但经济层仍偏轻
- 局外成长已形成追求感，但还缺更强的长期目标

### 4.2 治愈体验差距

已具备：

- 失败文案和“休息时刻”表达
- 不直接展示强烈负反馈
- 花语碎片与花语日记最小版

仍缺失：

- 更明确的保底进度继承机制
- 更丰富的失败后恢复设计
- 更丰富的日记内容、每日一句和关键节点文案编排

### 4.3 内容留存差距

已具备：

- 关卡推进
- 花园种植收获
- 花语碎片收集目标
- 今日花礼与每日任务最小版
- 花园装饰购买与氛围值最小版

仍缺失：

- 中长期收藏目标
- 更完整的局外装扮驱动力

### 4.4 商业化差距

已具备：

- 失败继续、双倍奖励的 UI 入口设计方向

仍缺失：

- 实际广告接入
- 广告触发频率与收益平衡
- 激励视频和核心循环的自然耦合

## 5. 当前版本完成度判断

如果按原始设计目标评估：

- 三消局内：约 75%
- 关卡推进：约 70%
- 花园系统：约 75%
- 合成系统：约 45%
- 治愈内容层：约 55%
- 商业化接入：约 10%
- 社交系统：0%

综合判断：

> 当前版本仍属于 “Pre-MVP 原型验证版”，但已经具备更明确的主循环骨架，并开始通过渐进解锁和结算降噪控制新玩家心智负担。

原因不是玩法不可用，而是核心卖点“消除 + 合成 + 花园治愈成长”仍需要继续打磨呈现顺序，避免多个局外系统过早同时争夺注意力。

## 6. 下一步策划原则

后续迭代不建议继续铺大系统，而应先把主循环真正闭合。

### 原则一：先补闭环，再扩内容

优先完成：

- 局内奖励结算
- 花园种植成长
- 合成升级
- 局外资源反哺局内

在这条链路稳定前，不建议先做社交、剧情、排行榜。

### 原则二：治愈感必须系统化，不只写在文案里

要把“休息时刻”做成规则，而不是弹窗文案：

- 失败保底奖励
- 连续失败缓冲
- 轻度恢复道具
- 每日安慰礼包

### 原则三：Meta 目标要可追逐

玩家需要知道“为什么再打一局”：

- 为了拿到某类花种
- 为了合成更高等级花
- 为了完成一条花语
- 为了点亮花园区域

### 原则四：微信小游戏版本必须轻量

首轮目标应聚焦：

- 单局可玩
- 次日有回访动力
- 广告位自然
- 包体与性能可控

### 原则五：先分层呈现，再继续扩系统

当前系统数量已经足以验证 Pre-MVP 主循环。后续新增功能前，必须优先确认：

- 新玩家前两局是否只接触必要入口
- 结算弹窗是否优先解释最关键成长结果
- 未接入或未闭环能力是否被隐藏或延后
- 新入口是否有清晰解锁时机和验证标准

## 7. 建议迭代路线

### 迭代 A：闭合最小主循环（P0）

目标：把“消除 -> 花园 -> 成长 -> 反哺局内”做成真正可持续玩的 MVP 骨架。

当前状态：

- 已完成统一结算与奖励发放
- 已完成关卡奖励配置化
- 已完成最小合成系统
- 已完成星光第二消费场景（开局祝福）
- 已完成失败保底与连续失败鼓励
- 未完成更完整的局内辅助项设计

### 策划需求

- 关卡胜利结算页显示：分数、星级、获得花种、获得星光
- 不同关卡或目标产出不同花种，形成收集差异
- 花园支持至少 3 级花朵成长与合成
- 星光增加至少 2 个用途：续关、开局道具/局内辅助
- 失败后给出安慰奖励，不让用户空手离开

### 实现需求

- 统一局内结算逻辑，不再让奖励散落在控制器回调里
- 打通花园合成数据结构与 UI 交互
- 补充资源产出表与关卡掉落表
- 明确局外资源消耗入口
- 增加主循环相关自动化测试

### 验收标准

- 玩家连续游玩 3 局后，能明确感知局外成长
- 玩家可通过花园成长获得再次闯关的帮助
- 即使失败，玩家也能保留一部分成长收益

- 已完成主菜单“花语日记”入口与最小展示页
- 已完成花语资源流自动化测试与 Harness 检查扩展
