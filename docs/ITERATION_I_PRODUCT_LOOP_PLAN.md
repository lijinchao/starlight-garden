## 1. 迭代目标

本轮只做一件事：

> 让完成前三局的玩家知道下一步为什么玩，并让关卡奖励、花园操作和可见变化形成一条可理解的闭环。

目标循环：

`看见待修复对象 -> 完成对应花朵目标 -> 获得对应花种 -> 选择种植或合成 -> 花园出现可见变化 -> 返回下一关`

本轮不做：

- 不增加新货币、活动、排行榜、社交或剧情章节。
- 不增加炸弹、彩球等传统三消特殊块。
- 不做自由摆放装饰，只做固定位置的可见点亮。
- 不接入微信、抖音 SDK；产品闭环通过后再做平台化。

### 1.1 服务的产品目标

- 闭合“关卡目标 -> 花种奖励 -> 花园行动 -> 下一关”的主循环。
- 让局外成长产生明确、可见且可复述的价值。
- 降低第 4 局集中开放造成的认知负担。

### 1.2 用户感知目标

1. 玩家能在首页 10 秒内说出当前唯一推荐动作。
2. 玩家能从局内和任一二级页面自主返回主页。
3. 玩家能看懂本关收集对象和完成后获得的花种。

### 1.3 功能与目标映射

| 功能项 | 服务目标 | 用户可感知结果 | 验证 |
|--------|----------|----------------|------|
| 局内主页入口 | 补齐导航闭环 | 不再被困在关卡中 | 自动化 + 截图 |
| 首页单一推荐 | 降低认知负担 | 明确下一步只做一件事 | 自动化 + 试玩 |
| 目标与奖励对齐 | 强化资源流 | 知道消除什么、带回什么 | 配置测试 |
| 教程生命周期 | 保持交互连续 | 引导不跨页面打断操作 | 自动化测试 |

## 2. 本轮触发原因

完成 3-4 局后的真实流程审计发现：

1. 第 4 局同时开放合成、装饰、花语、每日和开局祝福，入口增多但没有推荐顺序。
2. 花园恢复在第 3 局到达“微光庭”后结束，没有新的具体修复目标。
3. 装饰购买只改变“已点亮”和氛围值，装饰没有实际出现在花园画面。
4. 合成只显示等级变化，没有在操作前说明收获收益从 `10` 提升到 `25/45` 星光。
5. 空花盆会自动种下背包中的第一种花，玩家不能理解或选择资源去向。
6. 关卡 1-10 的目标全部以红玫瑰为主；关卡 11-20 也只增加蓝勿忘我，目标体验高度重复。
7. 局内没有清晰的主页/退出入口，二级页面虽有返回键，但主页没有“现在该做什么”的推荐。
8. 花语日记是纯被动进度页；今日花礼是任务清单，两者过早占据主页主导航。
9. 首次教程使用延迟任务启动，离开关卡后仍可能覆盖其他页面，场景边界不完整。

结论：当前不是“再加教程”能解决的问题，而是已有功能缺少价值表达和可见结果。

## 3. 产品裁决

### 3.1 首页只推荐一个下一步

- 首页始终保留一个主按钮，文案说明当前关卡将修复什么。
- 新系统首次可用时，只出现一个“新发现”任务，不同时引导多个入口。
- 花语与今日花礼降为次级入口；未达到可操作状态时不开放空页面。

### 3.2 解锁从局数阈值改为行为事件

| 能力 | 建议解锁条件 | 首次任务 |
|------|--------------|----------|
| 花园种植 | 第一次获得花种 | 选择一颗花种并种下 |
| 合成 | 背包首次存在可合成组合 | 预览并完成一次合成 |
| 花语日记 | 第一种花语达到 5/5 | 查看刚解锁的花语 |
| 今日花礼 | 第一次成功收获花朵 | 查看今日目标与可领取奖励 |
| 星光祝福 | 第一次失败后 | 解释星光如何反哺下一局 |
| 装饰 | 第一次收获后且星光足够 | 点亮一个固定装饰位置 |

同一次返回首页最多新增一个入口提示。其他已满足条件的能力进入等待队列。

### 3.3 花园操作必须产生可见结果

- 种植：点击空花盆后显示花种选择，不再自动消费第一项库存。
- 合成：操作前显示 `2 个 Lv.N -> 1 个 Lv.N+1` 和收获收益变化。
- 合成结果：花朵图形、等级和下一次收获收益同时变化。
- 装饰：购买前高亮固定落点，购买后长椅、灯笼、喷泉或花篱必须出现在背景上。
- 氛围值只作为汇总信息，不能替代实际画面变化。
- 若装饰可见素材尚未完成，隐藏购买入口，不交付纯数字购买。

### 3.4 关卡目标与奖励使用同一种花

- 前 5 关分别让红玫瑰、蓝勿忘我、紫薰衣草等目标与奖励花种对应。
- 第 6-10 关至少覆盖 4 种目标花，避免连续关卡只收集红玫瑰。
- 每关仍只保留一种主要目标，不新增复杂障碍。
- HUD 同时回答“收集什么、修复哪里、完成后获得什么花种”。

### 3.5 所有页面都有明确去向

- 局内增加暂停/主页入口；退出前说明本局未结算，不扣除资源。
- 花园、花语、花礼和设置保持一致的顶部返回入口。
- 空状态必须提供一个可执行命令，例如“去第 5 关获得蓝勿忘我花种”。
- 页面不使用长篇功能说明代替下一步按钮。

## 4. 分阶段实施

### I-1 导航与目标连续性

交付：

- 局内主页入口和退出确认。
- 首页单一推荐任务。
- 前 10 关目标花与奖励花种对齐。
- 修复教程延迟任务跨场景显示的问题。

阶段验收：

- 从局内、花园、花语和花礼均能在两次点击内回到主页。
- 关卡 1-10 至少使用 4 种目标花，没有连续 3 关相同的单一目标。
- 主页 10 秒内可看出当前推荐动作和预期奖励。

### I-2 花园操作价值可见

交付：

- 花种选择面板。
- 合成前后收益预览与完成反馈。
- 四种装饰的固定位置显示状态。
- 购买前预览和购买后局部点亮反馈。

阶段验收：

- 合成前玩家能看到材料消耗、结果等级和收获收益。
- 购买任一装饰后，不查看文字和数值也能从花园画面指出变化。
- 重进花园后种植、合成和装饰状态保持一致。

实现结果（2026-08-08）：

- 点击空花盆只打开花种选择，不会自动消费背包第一项；确认后种下指定类型与等级。
- 合成确认前展示 `2 个 Lv.N -> 1 个 Lv.N+1` 及 `10 -> 25 -> 45` 星光收益变化。
- 四种装饰均有固定落点、半透明购买预览、确认购买反馈和重进花园持久显示。
- Harness `190/190`、Godot 自动化测试 `365/365` 通过；真实视口截图已检查装饰、选种和合成预览。

### I-3 渐进解锁与回访引导

交付：

- 集中维护的 Meta 解锁策略。
- 行为事件驱动的解锁队列。
- 花语和花礼的可操作状态与空状态命令。
- 新入口首次到达、完成和返回主页的试玩事件。

阶段验收：

- 第 4 局返回主页时最多提示一个新能力。
- 未达到行动条件时不出现只能浏览、无法推进的入口。
- 完成首次 Meta 任务后，主页推荐自动收敛到下一关或下一个等待任务。

实现结果（2026-08-08）：

- 合成、花语、花礼、装饰和星光祝福由统一策略按真实行为进入固定优先级队列，不再依赖第 4 局同时开放。
- 每次回到主页最多提升一个等待能力；当前任务未完成时重复回访不会继续开放其他入口。
- 花语日记可直达当前关卡收集对应碎片；今日花礼可直达当前关卡或已有可收获对象的花园。
- 旧存档保留既有能力，新存档只按行为解锁；首次任务完成与二级页返回均写入本地试玩事件。
- Harness `191/191`、Godot 自动化测试 `394/394` 通过；真实视口截图已检查单入口提示、花语行动、花礼行动和装饰实物预览状态。

## 6. 验证门槛

### 自动化验证

- 关卡 1-10 至少覆盖 4 种目标花，目标与关卡花种奖励一致。
- 局内主页入口可返回菜单，并正确清理教程和处理中的动画。
- 空花盆不会在未选择花种时消费库存。
- 合成预览中的等级和星光收益与实际结算一致。
- 装饰购买后存在可持久化的固定显示状态。
- 同一时刻最多弹出一个首次解锁引导。

### 5 人观察式试玩

使用全新存档连续体验前 5 关，开发者不口头解释：

- 至少 `4/5` 能在第 4 局首页 10 秒内说出下一步该做什么。
- 至少 `4/5` 能说明合成后具体提升了什么。
- 至少 `4/5` 能仅凭画面指出购买装饰后的变化。
- 至少 `4/5` 能从局内和任一二级页自主返回主页。
- 至少 `3/5` 主动完成一次种植、合成或装饰，并继续下一关。
- 至少 `3/5` 认为第 2-5 关目标并非一直重复收集玫瑰。

### 可评估与停止条件

- 若 I-1 后仍有 `2/5` 以上玩家不知道下一步，不进入 I-2，先重做首页推荐。
- 若装饰购买后 `2/5` 以上玩家看不出变化，停止增加装饰种类，先修显示结果。
- 若入口仍造成明显犹豫，直接延后花语或花礼，不再增加说明弹窗。
- 未通过上述门槛前，不进入平台 SDK、商业化或新玩法开发。

## 7. 完成定义

迭代 I 只有在以下条件全部满足后才完成：

1. I-1、I-2、I-3 分阶段验收均通过。
2. 自动化测试和 Harness 全部通过。
3. 5 人观察式试玩达到核心门槛。
4. 玩家能理解“关卡目标 -> 花种 -> 花园变化 -> 下一关”的资源流。
5. 删除纯数字、无可见结果的购买或合成入口。
