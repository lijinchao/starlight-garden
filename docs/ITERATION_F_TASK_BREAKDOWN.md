## 1. 迭代目标

本轮只做一件事：

> 把项目从“带花园外壳的多系统三消原型”收敛为“前三局就能感知花园被自己一点点修复的治愈花园小游戏”，并避免前期体验落入普通消消乐式的系统堆叠。

本轮不做：

- 新增剧情、社交、活动、排行榜或微信/抖音平台接入
- 扩展花语内容、装饰目录、每日任务数量或新的局内数值系统
- 重新设计关卡数值曲线或补做传统三消特殊元素体系
- 重做花园布局、自由摆放或大地图区域系统

---

## 2. 服务的产品目标

本轮选择：

- 闭合主循环
- 强化治愈体验
- 优化资源反哺

原因：

- 当前版本主循环可以运行，但前三局仍会过早暴露花语、每日、装饰、合成、祝福、微风等多个 Meta 概念。
- 如果继续沿着“更多系统、更强留存”推进，会更像弱化版消消乐，而不是治愈花园题材小游戏。
- 本轮优先验证“每打一局都能看见花园被修复一点”是否足以成为继续游玩的理由。

---

## 3. 用户感知目标

玩家完成前三局体验后，应能明确感知：

1. 第一目标不是理解所有系统，而是先打一局，让花园恢复一点。
2. 每局结束后，都能看到花园状态发生明确变化，而不只是弹出奖励列表。
3. 前三局不会被每日任务、花语碎片、装饰商店、合成按钮、星光消费入口反复打断。
4. 到第 4 局前后，玩家才开始逐步接触花语、今日花礼、合成、装饰和局内辅助。

## 5. 功能定义

### F1-1 花园恢复阶段反馈

目标：

- 用一个简单、可见、可累计的恢复阶段替代前期对装饰、氛围值、花语碎片等多概念并行解释。

产品目标对应：

- 闭合主循环
- 强化治愈体验

实现要求：

- 存档增加 `garden.restoration_stage`，并与累计局数联动推进。
- 前三局每完成 1 局，花园恢复阶段推进 1 段，最多推进到第 3 段。
- 主菜单和花园页都要显示当前恢复阶段名称与一句简短描述。
- 主菜单、结算和花园都要说明“这次具体修好了哪个角落”。
- 胜利和失败结算首层摘要都要包含恢复阶段反馈。

验收标准：

- 新存档默认恢复阶段为 0。
- 完成第 1、2、3 局后，恢复阶段分别推进到 1、2、3。
- 第 3 局后继续游玩，恢复阶段不再无限增长。

可评估结果：

- 玩家不需要理解复杂经济，也能知道“我这一局让花园变好了”。

### F1-2 前三局 Meta 入口延后

目标：

- 让前三局只服务于“闯关 -> 带回花种 -> 回花园看变化”。

产品目标对应：

- 强化治愈体验
- 优化资源反哺

实现要求：

- 花语日记入口需要满足：`total_runs >= 3` 且已获得花语碎片或已解锁花语。
- 今日花礼入口需要满足：`total_runs >= 3`。
- 开局祝福确认需要满足：`total_runs >= 3` 且星光足够。
- 局内“星光微风”按钮需要满足：`total_runs >= 3`。
- 花园合成按钮和装饰购买区需要满足：`total_runs >= 3`。
- 失败弹窗在前三局不暴露继续挑战消费入口。

验收标准：

- 新存档在前 3 局内看不到花语日记、今日花礼、合成、装饰、开局祝福和局内微风入口。
- 累计完成 3 局后，满足条件的入口开始出现。
- 前三局失败时只能休息返回，不出现继续挑战消费提示。

可评估结果：

- 玩家先理解花园恢复，再理解资源消费与长线留存。

### F1-3 早期结算聚焦恢复结果

目标：

- 让前三局结算优先解释“花园恢复了什么”，而不是把长期系统一口气全推给玩家。

产品目标对应：

- 强化治愈体验
- 闭合主循环

实现要求：

- 前三局胜利结算首层摘要优先显示恢复阶段与花种结果。
- 前三局失败结算首层摘要优先显示恢复阶段与完成度。
- 普通花语碎片、首通数值、消费型提示不进入前三局首层摘要。
- 第 4 局及之后恢复为完整的当前简化摘要结构。

验收标准：

- 自动化测试确认前三局首层摘要包含“花园恢复”信息。
- 自动化测试确认前三局首层摘要不显示普通花语碎片进度。
- 手动验证前三局结算不会把消费入口和长期入口一并暴露。

可评估结果：

- 玩家对“下一步做什么”的理解更直接，不必先消化多个系统名词。

## 6. 数据与资源流

本轮不新增复杂经济，只新增一个阶段化恢复反馈：

- 资源来源：胜利结算、失败结算、花园种植收获
- 资源用途：第 4 局后继续用于续关、开局祝福、局内微风、装饰购买
- 资源反馈：前三局更强调“恢复阶段变化”，弱化消费入口说明

新增数据字段：

- `garden.restoration_stage`：记录花园当前恢复阶段，默认 0，前三局最高推进到 3。

说明：

- 恢复阶段不是新经济货币，而是对主循环结果的可见表达。

---

## 7. UI / 交互要求

- 主菜单始终显示当前花园恢复阶段和一句简短引导语。
- 主菜单始终给出当前修复角落的具象提示，例如“第一簇新芽”“第一朵花”“门前微灯”。
- 花园页始终显示恢复阶段；装饰区未解锁前不显示购买列表。
- 前三局胜利弹窗主按钮文案改为更接近“回去看看变化”，弱化连打下一关心智。
- 前三局胜利或失败后，主按钮都应真实进入花园，而不是只返回主菜单。
- 前三局失败弹窗不出现继续挑战入口。
- 如果本局推进了恢复阶段，进入花园后要出现一次短暂的恢复到达动画，而不只是静态页面刷新。
- 花园页要用稳定可见的方式强调当前修好的角落，而不是只显示抽象阶段名称。

## 8. 验证清单

### 自动化测试

- 默认存档包含 `garden.restoration_stage`。
- 胜利和失败结算都会同步恢复阶段。
- 恢复阶段在第 3 局后不再继续增长。
- 花语日记、今日花礼、合成、装饰、开局祝福、局内微风都在 `total_runs < 3` 时隐藏。
- 前三局结算首层摘要包含恢复阶段且不显示普通花语碎片进度。
- 前三局结算首层摘要包含当前修好的角落名称。

### 手动验证

- 重置存档后，主菜单能看到花园仍在恢复中的提示，但看不到花语日记和今日花礼。
- 第 1、2、3 局结束后，返回菜单或进入花园，看到恢复阶段名称发生变化。
- 第 1、2、3 局结束后，菜单、结算和花园对“修好了哪个角落”的表述保持一致。
- 前三局在花园页只能种植和收获，看不到合成按钮与装饰购买入口。
- 前三局开始游戏不弹开局祝福，局内不显示星光微风按钮。
- 前三局失败弹窗不显示继续挑战消费入口。
- 前三局从结算回到花园时，如果恢复阶段推进，要看到一次“花园恢复到某阶段”的短暂反馈。
- 第 3 局结束后，再进入菜单与花园，花语、今日花礼、合成、装饰与辅助入口开始按条件出现。

### 评估问题

1. 玩家是否能在第一局后明确感知“花园恢复了一点”？
2. 前三局减少 Meta 暴露后，是否更容易判断下一步行动？
3. 如果去掉恢复阶段反馈，游戏是否又会退回普通奖励列表驱动？
4. 第 4 局后再逐步开放系统，是否比当前版本更符合治愈休闲小游戏定位？

## 9. 完成定义

当以下条件都满足时，迭代 F 才算完成：

1. 当前迭代文档、README、状态文档、AGENTS 和 Harness 均指向迭代 F。
2. 存档已支持 `garden.restoration_stage`，并可在前三局稳定推进。
3. 主菜单、花园页和结算弹窗都能给出恢复阶段反馈。
4. 前三局 Meta 暴露已收敛到闯关、花园、种植收获三条主线。
5. 自动化测试覆盖恢复阶段与前三局入口收敛。
6. 手动验证文档补充恢复反馈与第 4 局解锁验证步骤。
7. `./run_harness.sh` 通过。
