# Postmortem — 连续两轮反馈层投入都没有产生感受

Date: 2026-08-25
Owner: @lijinchao

## Impact

迭代 M（花园角落指示器、接近目标升温与完成高潮、结算情绪文案）与迭代 N（具名照料对象「小星」）都已实现，Harness 与自动化测试全绿，但项目所有者复玩后两次都判断“无感”。两次投入合计新增了一个系统、十几个事件与断言，却没有改变玩家体验。

## Detection

- M 完成后复玩：棋盘下方花园角落感知不到变化；特效“本质上不会带来任何玩法或者情绪的价值”；结算文案“当前并不重要”。
- N 完成后复玩：一个字，“无感”。
- 两次都不是崩溃或数值错误，自动化无法发现；只有产品验证层能发现。这暴露了交付流程的一个漏洞：我们把“工程完成 + 测试全绿”当成了“这一轮有价值”。

## Timeline

- 迭代 M 的 M1-M4 落地，Harness 204/204、测试 517/517。
- owner 复玩判断机制依旧、反馈无价值。
- 新增 `CORE_LOOP_RETHINK.md`，诊断为“核心动词无决策压力 + 无可依附照料对象”，owner 选定方向 A。
- 迭代 N 按方向 A 引入具名照料对象，Harness 206/206、测试 538/538。
- owner 复玩：无感。

## Root cause

两轮都只改变了“呈现”，没有改变“决策”或“关系”：

1. **M 的反馈层没有让任何一次操作变得更值得思考。** 指示器、升温、高潮流，本质仍是数值加特效。
2. **N 的照料对象没有需求、没有自主行为，且位于焦点之外。** 一个 emoji 加一行字、对任何消除都同样满意的进度条，不构成角色，因此无法产生依恋。

判断失误在于：把“玩家没感受到”理解成“反馈不够多”，而不是“没有值得感受的东西”。这是流程问题——迭代 N 的完成定义只要求“说得出名字”，门槛太低，允许一个被动计量表通过。

## Response

- 在 `CORE_LOOP_RETHINK.md` 中记录：“A-lite（被动计量表）已被证否”，并把方向 A 细化为 **A-real**：对象必须有具体需要、有自主行为、且玩家的取舍会影响它。
- 增加红线：在能改变局内决策或产生自主对象之前，不再新增任何反馈层、特效或元系统。
- 后续迭代的完成定义必须包含“证否标准”，而不只是“能不能说出名字”。
