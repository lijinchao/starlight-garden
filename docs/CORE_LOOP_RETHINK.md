## 1. 先给判断

当前版本的问题不是“缺少某个功能”，而是两件事同时缺失：

1. **核心动词本身不产生乐趣**：交换三消在这套规则下几乎没有“坏招”，玩家在找现成三连，而不是在做决策。
2. **没有值得照料的具体对象**：花园是背景图与阶段数字，没有具名、有状态、会回应的个体。

在这两个前提未变之前，继续叠加反馈、特效、内容或元系统，都不会产生乐趣与情绪价值。迭代 M 的 M2（花园角落指示器）、M3（升温与高潮特效）、M4（结算情绪文案）就是反例：它们让“呈现”更完整，但没有改变“玩什么”和“在乎谁”。

---

## 2. 支撑证据

- owner 复玩判断：推进玩法依旧；棋盘下方花园角落感知不到变化；M3 特效“本质上不会带来任何玩法或者情绪的价值”；M4 结算“当前并不重要”。
- 迭代 N 引入具名照料对象后，owner 复玩仍判断“无感”，且自动化全绿。这证明“加一个被动的对象”不足以产生依恋。详见 [postmortems/0002-feedback-layers-without-meaning.md](./postmortems/0002-feedback-layers-without-meaning.md)。
- 可玩性缺陷：局内无法返回主页、胜利后被迫继续过关（已在本次修复并加回归测试）。
- 项目自身记录：差异化玩法从“已实现，未验证”变为“初测为负”（`CURRENT_PRODUCT_AND_ARCHITECTURE.md`）。
- 迭代 K、L 的复盘也指向同一件事：固定满格棋盘让局内趋同，换目标数字不增加新鲜感。

---

## 3. 根因（四条）

### 3.1 交换没有决策压力
满格 `7 x 7`、单一收集目标、步数相对充裕，几乎不存在“这一步会害我”的局面。乐趣来自**约束与后果**（有限步数、会阻挡的障碍、必须提前铺垫的连锁），而不是消除动画。当前两者都弱。

### 3.2 两端都被抹平
为了“低压力”，失败代价被移除，成功收益也被降噪。没有紧张就没有释放；**“治愈”不是没有张力，而是张力之后的安放**。把两端都削平，中间自然没有起伏。

### 3.3 因果被结算垄断
所有回报集中在结算，局内行为对“玩家在乎的东西”没有持续影响。花园是独立界面加计数器，不是一个会因为你的操作而改变的**对象**。

### 3.4 没有可依附的照料对象
主题是“治愈 / 花园”，但花园里没有一个**具名、有状态、会回应**的个体；花语是静态文本。没有对象就没有依恋，也就没有情绪价值。

附带问题：14 个 Autoload 的系统数量远超核心质量，属于“宽而浅”。

---

## 4. 三个重设方向（择一，不要同时做）

### 方向 A：照料对象优先（建议先验证）— 已细化为 A-real

- 一句话：把三消降为“照顾一个具体对象”的手段，对象有自己的需要与自主行为。
- 玩家情感：依恋、惦记与“它在等我”。
- 保留：现有交换三消、花园经济、局内框架。
- 代价：中偏高。需要角色表现、需要系统、离线行为与回访界面。
- 风险：如果交换本身仍无聊，依恋会被执行层面的枯燥拖垮。

**A-real 的三条必要条件（缺一条就退回被动计量表）：**

1. **有需要**：它在局内提出具体请求（例如“想要光”），而不是对任何消除都同样满意。
2. **有自主**：玩家不在时它会自己行动，回来能看到“它做了什么”，产生惦记与惊喜。
3. **有取舍**：为了它而改变玩法决策——喂它 A 就要放弃 B，消除不再只是找现成三连。

**证否标准（先于实现写清）：** 完成 A-real 最小切片后，试玩者若仍无法描述“它在要什么 / 它做了什么 / 我为什么那样选”，则方向 A 判死，转 B 或 C。

**已证否的形态：**

- A-lite（具名但被动、无需要、无自主、位于焦点之外的计量表）在迭代 N 被证否。
- **A-real（有需要、但制造了并列目标）在迭代 O 被证否**：它把“照料诉求”和“上方收集目标”同时放进一局，玩家被两个目标拉扯，产生割裂，两个都不满足。详见第 8 节。

### 方向 B：空间解题优先

- 一句话：放弃“收集数量”，把每关做成步数紧张的棋盘谜题（障碍、单向掉落、拓扑关系），清风路径作为关键工具。
- 玩家情感：解开的满足感与心流。
- 代价：高。关卡设计成本高，目标用户从“放松”转向“动脑”。
- 风险：与“治愈 / 低压力”的现有定位冲突。
- 最小验证：3 个手工谜题关，观察是否有人主动重试而不是退出。

### 方向 C：仪式优先（去掉三消核心）

- 一句话：承认交换三消是红海商品，把核心动作换成慢节奏的照料仪式（种、摆、抚、画），三消降为可选小游戏。
- 玩家情感：直接的平静与专注。
- 代价：高。产品重塑，弃用大部分局内代码。
- 风险：最大。但如果 A、B 都无法产生乐趣，这是最诚实的选择。

---

## 5. 建议路径

方向 A 已判死。剩下的只有两条，且必须二选一：

- **方向 B：把核心动词本身做成值得玩的谜题。**
- **方向 C：承认交换三消是红海商品，把核心换成花园经营 / 照料仪式。**

判断标准只有一条：**这个核心动词单独拿出来、去掉所有外围之后，好不好玩？** 如果不好玩，它就不配当核心，花园和情绪都救不了它。

**推荐先做 B**：它复用现有核心，是验证“我们能不能把交换三消做得有乐趣”的最短路径。若 B 的最小验证仍不成立，再走 C 就不再是逃避，而是结论。

---

## 6. 本轮明确不做

- 不再叠加任何“数值 + 特效”型反馈。
- 不扩每日布局、不新增机关与元系统。
- 不在方向选定前重写核心或新增货币。
- **红线：在能改变局内决策或产生自主对象之前，不再新增任何反馈层、特效或元系统。**（来源：[postmortems/0002-feedback-layers-without-meaning.md](./postmortems/0002-feedback-layers-without-meaning.md)）

---

## 7. 需要 owner 裁决的三个问题

方向 A 的裁决已完成（判死）。剩下需要裁决的是：

1. 接受 **B（做深三消谜题）** 还是 **C（换成花园经营 / 照料仪式为核心）**？
2. 是否同意执行“**单一闭环**”原则：一局只有一个目标、一个动作只有一个可见后果，其余系统一律移出主线？

在这两个问题有答案之前，不应进入实现。

## 8. 判断补充（2026-08-25）：什么都想要，导致参与度差

owner 在迭代 O 后指出：局内同时存在“照料对象的请求”和“上方收集花通关”两个目标，玩家被两套诉求拉扯，产生**割裂**；并把这一点与 TOP 小游戏的通病联系起来——**什么都想要，反而忽略了玩法本身和玩游戏带来的满足感**。

这条判断成立，且被我们自己的历史验证：

| 迭代 | 我们加了什么 | 结果 |
|------|--------------|------|
| K / L | 落叶、方向清风、晨露连锁、每日风庭 | 局内趋同，未验证 |
| M | 花园角落指示器、升温高潮、结算文案 | 无感 |
| N | 具名照料对象 | 无感 |
| O | 三个需要 + 按颜色喂食 | 与关卡目标割裂 |

**单一闭环原则：**

1. 一局只有一个目标。任何与它竞争的系统都必须移出局内。
2. 一个动作只产生一个可见后果，且后果要在玩家正在看的地方。
3. 核心动词必须单独成立——去掉所有外围，它仍然值得玩。
4. 满足感来自“一个清楚的动作 → 一个清楚的反馈 → 一次清楚的成长”，而不是系统数量。

**对当前代码的直接含义：** 照料对象（O）、每日风庭（L）以及并列的多个 Meta 都在提供并列目标，属于要移出主线或删除的对象；在选定 B/C 之前，不再向它们投入。

## 9. 结论更新（2026-08-25）：方向 B 的核心动词成立

迭代 P 沿方向 B 连续做了：单一空间目标 → 清风块持久化与组合 → 不可移动石块 → 关卡意图解探针 → “石块只能被清风击碎” + 6-8 关重做。结果是：

- **机械层**：`scripts/tools/puzzle_depth_probe.gd` 用无前瞻贪心机器人与会攒清风的前瞻规划机器人跑同一批种子。第 6-8 关的贪心通过率为 0.20 / 0.12 / 0.20，规划为 0.55 / 0.55 / 0.53——满足“贪心过不了、规划能过”，即关卡确实存在一个需要计划的解。
- **玩家层**：owner 试玩确认 C1-C3 全部符合——能复述下一步计划、会出现“先留着清风等布局”的延迟满足、失败后主动重试并换策略。
- **自动化基线**：Harness 230/230、Godot 959/959、`harness gates` exit 0。

**结论：按第 5 节的判断标准（去掉所有外围后核心动词是否值得玩），方向 B 通过。** 交换三消 + 清风击碎石块本身已经能提供“想一下、想通、解开”的满足感，不再需要一个并列系统来撑。

**这不等于产品完成。** 它只证明“局内值得玩的决策层”这一前提成立。第 6 节的红线（在能改变局内决策之前不加反馈层）的前提已经满足，因此花园/照料可以作为**回报层**接回来——此时它不再是逃避，而是给一个已经成立的核心配情绪回报。那是方向 C 的内容，现在有了接回去的资格。
