# 星光花园 - 主题与玩法复盘

## 文档信息

| 项目 | 内容 |
|------|------|
| 文档性质 | 下一迭代前产品裁决 / 用户体验验证依据 |
| 更新时间 | 2026-08-08 |
| 对应版本 | 0.1.0-pre.1 |
| 适用阶段 | Pre-MVP 产品验证 |

本文不以“当前流行什么就复制什么”为结论，而是用近期市场信号检查项目主题、用户、场景和玩法是否仍匹配。

---

## 1. 结论

### 1.1 方向保留，但需要进一步聚焦

保留：

- 花园恢复主题。
- 低门槛交换三消。
- 四连触发清风唤醒。
- 胜负都能留下少量恢复痕迹的低压力表达。

收缩：

- 不再以“女性向”作为功能堆叠理由。
- 合成、花语、每日、装饰都降为延后验证的 Meta，不与首局争夺注意力。
- 不跟随螺丝、箭头、挪车、收纳等短周期热门玩法切换核心规则。
- 不用复杂剧情、角色关系或活动系统掩盖局内玩法不足。

当前一句话定位保持为：

> 一款让玩家用短局花朵三消，把沉睡花园一角一角吹醒的治愈系小游戏。

### 1.2 当前最大偏移不是题材，而是体验证据不足

主题和平台场景基本匹配，但当前“清风唤醒”本质仍是四连后的额外目标数值和特效。它比普通三消多了一层表达，还没有形成足以独立记住的规则体验。

因此下一步不是增加第二套特色机制，而是验证：

1. 玩家是否注意到清风。
2. 玩家是否理解清风正在改变具体花园角落。
3. 移除清风后，体验是否明显变弱。
4. 一局结束后，花园变化是否足以驱动下一局。

## 2. 近期市场信号及其边界

### 2.1 可以采用的判断

- 小游戏仍是增长市场，但产品竞争已从“能上线”转向留存、内容更新和长期经营。2026 微信公开课披露的 2025 年数据中，百万 DAU 产品和季度流水千万元产品数量继续增加，说明机会与竞争同时扩大。
- 花园和种植题材仍有用户吸引力。第三方榜单和产品报道显示，《我的花园世界》在 2025 年末至 2026 年仍位于微信小游戏畅销榜前列。
- 抖音提供性别、年龄、地域等用户画像能力，意味着平台选择和投放素材应由真实数据校正，而不是仅凭“25-40 岁女性”假设。
- 平台启动速度依赖首包体积和首场景复杂度；分包是正式平台化必须纳入的工程能力，不是上线后的附加优化。

### 2.2 不能直接推出的结论

- 花园题材上榜，不等于“花园 + 三消”自然成立。
- 热门轻玩法适合广告素材，不等于适合作为长期核心玩法。
- 女性用户较多，不等于需要粉色、花语、合成、装扮、剧情全部叠加。
- 榜单表现无法替代本项目的首局完成率、清风识别率和再开局率。

## 3. 目标用户与使用场景

### 3.1 核心用户假设

优先测试人群：25-40 岁、日常使用微信或抖音、偏好轻量益智和舒缓视觉的用户，女性为主要招募方向，但不把性别作为排他条件。

核心需求不是“女性功能”，而是：

- 无需学习复杂规则。
- 2-5 分钟能获得一次完整反馈。
- 中断后没有明显损失。
- 视觉变化可见，而不是只增加资源数字。
- 有轻微技巧空间，但不制造高压失败。

### 3.2 优先场景

| 场景 | 时间预算 | 设计要求 |
|------|----------|----------|
| 通勤或排队 | 2-3 分钟 | 进入快、可随时中断、无长文本 |
| 午间短休 | 3-5 分钟 | 一局和一次花园反馈构成完整闭环 |
| 睡前放松 | 5-8 分钟 | 低刺激反馈、避免强制广告和多入口催促 |
| 短视频导流 | 前 10 秒 | 立刻可操作，首个明显反馈无需理解 Meta |

原 GDD 的“单局 5-10 分钟”偏长。当前验证目标改为单局约 2-4 分钟，完整一次“关卡 + 花园反馈”控制在 5 分钟内；真实时长必须通过试玩记录确认。

## 4. 玩法取舍

| 玩法/趋势 | 决策 | 原因 |
|-----------|------|------|
| 交换三消 | 保留 | 学习成本低，适合碎片场景，但只能作为交互底座 |
| 花园恢复 | 强化 | 是题材、目标和局外反馈的统一载体 |
| 清风唤醒 | 强化并验证 | 当前最接近独特记忆点，先做深度而非增加数量 |
| 花朵合成 | 延后 | 可提供长期追求，但当前会稀释“修复角落”主线 |
| 花语收集 | 延后 | 可补情绪价值，但不能替代玩法反馈 |
| 装饰购买 | 延后 | 固定购买当前缺少表达力，自由摆放又会扩大工程范围 |
| 螺丝/箭头/挪车/收纳 | 不跟随 | 热度不构成主题适配，切换会推翻现有规则和内容资产 |
| 炸弹/彩虹等传统特殊块 | 暂不做 | 会增强普通三消感，削弱清风的唯一性 |
| 重剧情/角色关系 | 不进入 MVP | 内容成本高，且当前核心循环尚未被证明 |
| 排行榜/公会/强社交 | 不进入 MVP | 与低压力、私人放松场景冲突 |

## 5. 主题表达原则

### 5.1 主题不是背景图

每局必须同时回答：

- 正在修复哪里。
- 棋盘上的什么行为推动了修复。
- 结束后哪里发生了可见变化。

仅修改 HUD 文案或结算文字，不算主题玩法成立。

### 5.2 清风机制的演进边界

当前版本只验证四连清风，不立即扩规则。验证通过后，下一层优先考虑“清风路径吹开叶片/薄雾并改变棋盘局部”，而不是增加炸弹、彩虹花和多种道具。

允许演进：

- 清风经过的格子有明确轨迹。
- 叶片、薄雾、花苞等主题障碍被清风改变。
- 棋盘变化与花园角落变化使用同一对象和语言。

禁止演进：

- 同时加入多种特殊块。
- 把清风改成付费按钮的别名。
- 只有全屏特效，没有可感知规则结果。

### 5.3 治愈不等于没有目标

失败可留下少量恢复痕迹，但成功必须明显更有价值。建议验证“失败保留观察到的痕迹，胜利完成角落唤醒”的双层结果，避免当前按总局数推进导致成功和失败价值过于接近。

## 6. 下一阶段验证门槛

### 阶段 A：5 人观察式试玩

使用全新存档，让 5 名目标用户连续体验前 5 关。开发者只观察，不提前解释清风、恢复和 Meta。

通过条件：

- 至少 4/5 能在第一局后说出正在修复花园或具体角落。
- 至少 4/5 注意到四连后的清风反馈。
- 至少 3/5 主动开始第 4 局。
- 至少 4/5 在前三局没有因入口、资源或弹窗产生明显困惑。
- 每人记录单局时长、停顿点、误触点和一句原话反馈。

任一核心条件未达成，不启动新系统开发，只调整首局、清风反馈或结算到花园的连接。

### 阶段 B：20-30 个无引导试玩会话

阶段 A 通过后再进行。当前只建立指标口径，不预设其等于正式上线 KPI。

建议记录：

- 首次可操作耗时。
- 第 1 关完成率和中位时长。
- 第 3 关到达率。
- 第 4 关开始率。
- 清风首次触发关卡、触发次数和反馈停留时长。
- 关卡结束后进入花园率及再次开局率。
- 第 4 局集中解锁后的停顿、误触和退出。

### 阶段 C：下一迭代裁决

| 观察结果 | 下一步 |
|----------|--------|
| 清风被注意且再开局意愿较强 | 做深清风与主题障碍，不扩 Meta |
| 清风被注意但花园驱动力弱 | 优先强化角落前后变化和恢复目标 |
| 清风未被注意 | 调整触发频率、轨迹和规则结果 |
| 三消本身被认为重复或乏味 | 先试验单一清风路径规则，仍不堆传统特殊块 |
| 第 4 局明显困惑 | 拆分解锁策略，延后低价值入口 |

## 7. 下一迭代前的产品红线

任何新需求进入开发前必须回答：

1. 它强化的是“修复角落”还是外围留存系统？
2. 玩家在 10 秒内能否感知它？
3. 它是否让清风更独特，而不是让产品更像普通消消乐？
4. 能否用 5 人试玩或自动化契约验证？
5. 删除它是否会明显削弱核心体验？

其中 1、3、4 无法回答时，不进入当前版本。
